# 性能说明与复现

星汐当前面向单用户本机工作台。性能优化不等于无限规模支持，也不代表 DeepSeek 网络请求的延迟承诺。

## 已处理的增长瓶颈

- **原文按需读取**：空间快照只包含来源标题、类型、时间及字符数。点击来源或手动整理时才取正文，任务轮询只查询任务状态。
- **记忆倒排索引**：SQLite `entry_terms` 保存英文词、中文单字/双字及权重。确认、修改、归档与索引更新处于同一事务；已有数据库首次启动自动回填一次。每次检索只取匹配结果，空查询直接 LIMIT，不把全部正文读入 JavaScript 打分。
- **会话分页**：Web/MCP 默认返回最新 100 条，使用 `nextBefore` 游标读取更早消息。每轮模型上下文只查询最近 20 条，再应用约 20,000 字符预算。写入和重试查重不再读取整段历史。
- **完整保存语义**：「收为资料」由服务端读取会话全部消息，不会把当前页面的 100 条误当成完整聊天；超过 100,000 字符会明确拒绝，要求选片段导入。
- **图谱与列表**：一次构建节点关系度，避免排序比较器重复扫描所有边。星图最多显示 160 个节点、500 条边，并提示筛选；星册每批 60 条。完整集合仍可筛选，不伪造关系。
- **任务轮询**：一次请求结束后再安排下次轮询，隐藏页面暂停查询，任务结束时才刷新空间资料。

## 合成数据基准

2026-11-06，Apple M4、Node v26.4.0，本地 SQLite，热运行；5000 条记忆、50 份资料（49 份各 50,000 字符，另有短证据源）、10000 条消息，图准备使用 10000 条关系。全部为测试生成文本，未使用真实聊天。对照代码为 `perf-baseline` 标签。

| 操作                 | 优化前中位数 | 优化后中位数 | 优化后 p95 |
| -------------------- | -----------: | -----------: | ---------: |
| 选择性记忆检索       |     58.32 ms |      0.13 ms |    0.18 ms |
| 构建并序列化空间快照 |    123.60 ms |     67.07 ms |   71.62 ms |
| 读取会话             |     50.11 ms |      0.37 ms |    0.56 ms |
| 追加消息             |     71.32 ms |      0.20 ms |    0.59 ms |
| 图谱数据准备         |   未单独计时 |      1.89 ms |   16.90 ms |

空间快照体积：11,532,508 → 4,182,987 字节。会话响应体：5,282,951 → 54,663 字节。会话读回变小是**分页**的结果，所有旧消息仍然存在。每项重复 15 次，快照重复 5 次，因此 p95 仅是小样本观测；首次索引回填、完整浏览器绘制、冷缓存和模型网络延迟不在这些计时中。合成数据重复度高，实际索引大小与检索速度取决于文本和查询分布。

复现：

```sh
npm run benchmark
# 包含优化前版本的对照；需要完整 Git 历史及 perf-baseline 标签
npm run benchmark -- --baseline=perf-baseline
```

脚本在临时目录生成、校验并清理测试数据库，不连接模型、不读取 `.local/`，不会消耗 API 额度。自动化测试另外检查索引随修改/归档变化、命名空间、分页连续性和图谱边界。速度随硬件而变，不把某个毫秒数当作跨机器 CI 断言。

## 仍存在的规模边界

- 网页已切换为按页面摘要与服务端分页；旧兼容快照接口和完整导出仍可能读取全空间，不能把它们当首屏接口使用。全空间计数仍随条目量增长，高频词、极高出度节点和很多修订也有额外成本，尚无百万条规模承诺。
- 中文双字与英文整词索引是字面检索，不是语义 embedding。常见词查询的候选集合比选择性测试查询大，不能用上表代表所有查询。
- SQLite 为同步单进程写入；初次迁移大型数据库会阻塞启动。不要多个服务实例共用同一数据目录。
- 160 节点的星图是浏览窗口，后续仍需聚类、标签避让与按需展开。SVG 上限控制节点数，不保证低端机器的特定帧率。
- 没有分布式任务队列、多用户并发承诺或后台自动模型调用。单个提炼任务串行执行，避免抢占与意外费用。

## 自动聊天记忆增量基准（2026-11-06）

同一 Apple M4 / Node 26.4.0，新增 10,000 条消息（5,000 条用户消息）的 FTS5 索引，15 次热缓存测量。每条用户消息原文约 125 个字符，数据为虚构合成。运行 `npm run benchmark` 即可复现数据生成与正确性断言；不同机器和并行负载结果会不同。

| 项目               | 中位耗时 |      P95 |
| ------------------ | -------: | -------: |
| 特定关键词聊天召回 |  0.39 ms |  0.62 ms |
| 高频词聊天召回     | 12.16 ms | 12.96 ms |
| 最近聊天原话       |  0.16 ms |  0.43 ms |
| 单条消息写入与索引 |  0.34 ms |  2.70 ms |

特定关键词响应体 889 bytes。检索只返回最多 12 条原文片段，模型每轮最多取 8 条，每条最多 1,200 字符。索引与消息事务写入，不额外调用模型。

本次聊天索引阶段测试的空间完整快照为 4.18 MB，中位 133.12 ms，暴露了后续页面分页改造要处理的规模瓶颈。网页现已使用下一节的分页接口。旧基准中的 67 ms 与本次数据不能当成跨运行的硬性性能保证。初始化旧库时的全文索引回填会占用启动时间；极大数据库仍需要后续分批迁移设计。

## 回答参考记录的留存成本

运行 `npm run benchmark -- --evidence` 可额外造入 5,000 份参考记录，每份 8 条知识、8 条原话、20 条近期消息标识，共 180,000 个参考项。它使用合成数据，不调用模型，不访问真实数据目录。

Apple M4 / Node 26.4.0，后一轮 15 个样本：

| 操作                         | 中位耗时 | 小样本 p95 |
| ---------------------------- | -------: | ---------: |
| 单份参考读取及 JSON 序列化   |  1.98 ms |    2.37 ms |
| 追加回答及保存参考，同一事务 |  5.24 ms |   12.01 ms |

单份响应 14,442 字节。批量填充后、计时追加前，SQLite `page_count × page_size` 的增长为 75,849,728 字节；这是数据库逻辑分配页增长，不含 WAL/SHM 文件，也不是峰值内存。之前一轮同机读取/保存中位分别为 1.03 / 3.11 ms，不应将其视为固定延迟。

审计记录仅在用户点开时读取，不随全部会话列表返回；本阶段每份最多 36 项，摘要扩展后的上限见末节。合成正文较短且重复，并非所有截断字段都填满；长期磁盘占用仍会随回答数量与提供的参考长度增长。删除通过目标索引找到所有引用，删除成本与实际引用数量相关，不能宣称常数时间。

## 在线备份与主线程响应

`npm run benchmark -- --backup` 在相同的 5,000 条知识 / 50 份资料 / 10,000 条消息 / 10,000 条关系合成库上执行工作线程备份、校验与恢复。复制过程中主线程每 10 ms 尝试读取一次最近 20 条消息，测量实际读取耗时及事件循环监测值。

Apple M4 / Node 26.4.0 的一次运行：数据库 62,996,480 字节；创建（含校验、哈希）1,050.86 ms，重新校验 766.34 ms，恢复到新目录（含校验）847.40 ms。主线程获得 254 个读取样本，中位 0.29 ms；事件循环延迟监测最大值 12.71 ms，监测分辨率为 10 ms。它不是 HTTP 或浏览器响应延迟，也不是跨机器 SLA。

这验证了整库操作期间主线程仍能继续读会话。不能据单次热缓存运行断言磁盘竞争为零、内存不增长或所有规模均有相同速度；持续写入也可能使在线复制重试。完整性校验随库大小增长，其成本不能靠分页消除，因此与常用请求分线程执行，并明确展示任务状态。

## 分批摘要与跨会话召回

新增 `npm run benchmark -- --summaries`：在前述合成库的 10,000 条消息上建立 250 批、每批 8 项助手摘要，共 2,000 项；测试直接构造带真实消息引用的候选并审阅，不调用模型。2026-11-06，Apple M4 / Node 26.4.0，每项 15 次热运行，包含 JSON 序列化：

| 操作           | 中位耗时 | 小样本 p95 |
| -------------- | -------: | ---------: |
| 选择性摘要召回 |  0.34 ms |    0.44 ms |
| 高频词摘要召回 |  6.06 ms |    7.03 ms |
| 20 份摘要目录  |  0.51 ms |    0.98 ms |

高频词返回最多 4 项，响应 5,713 字节。建立批次、出处映射、摘要正文及索引后，数据库逻辑页增长 5,132,288 字节，不含 WAL/SHM 和峰值内存。正文为短且重复的合成数据，不能推算所有真实用户的存储成本。覆盖计数仍随当前会话消息数/批次数增长，尚未宣称百万条规模。

模型整理另有每批最多 40 条 / 24,000 字符的输入预算，生成时间和模型费用不在此表中。普通消息追加不调用摘要模型，不遍历旧摘要。审核或归档只更新一批及其最多 8 项搜索记录；检索返回有界不代表高频词匹配的数据库工作恒定。

新增摘要参考后单份回答参考最多 40 项（原 36 项加 4 项摘要）；前文 5,000 份参考的基准仍是每份 36 项，不能当作填满 40 项后的测量。

## 纠正、时间变化与冲突审阅

`npm run benchmark -- --changes` 在同一基础合成库中增加 1,000 条变更，对应 500 个知识目标，每个目标两次生效记录。测量包括独立依据资料、变更正文和索引；不调用模型。2026-11-06，Apple M4 / Node 26.4.0，各项每轮 15 次，包含 JSON 序列化：

| 操作               | 第一轮中位 / 小样本 p95 | 第二轮中位 / 小样本 p95 |
| ------------------ | ----------------------: | ----------------------: |
| 选择性变更召回     |          0.63 / 0.89 ms |          0.63 / 0.83 ms |
| 高频词变更召回     |          5.36 / 6.65 ms |          5.08 / 6.20 ms |
| 20 条变更目录      |         0.51 / 55.84 ms |          0.45 / 0.79 ms |
| 未被变更的知识查询 |          0.18 / 0.57 ms |          0.18 / 0.34 ms |

两轮高频词响应均为 7,819 字节。数据库逻辑页分别增加 4,345,856 / 4,329,472 字节，包含独立原始资料，不含 WAL/SHM 或峰值内存。目录第一轮存在明显慢样本，第二轮没有复现，不将其隐藏或解释为确定的原因。

计时位于已填充数据、重复访问的进程中，未对每个操作单独执行严格预热；不是冷启动或 HTTP 全链路测试。结果受缓存、调度和磁盘状态影响。合成文本短且重复，尚未测量百万记录、填满所有字段或多用户并发。查询返回上限不等于 SQL 扫描数量上限，尤其高频词和状态筛选仍需关注执行计划。

变更参考使每份回答参考上限从 40 增至 46。历史 36 项审计基准保持原有语义，不据此承诺满 46 项时的写入延迟。变更的创建和审阅不调用模型；真实模型的两次虚构验收仅用于核对新日期与未决冲突表达，不参与性能数字。
